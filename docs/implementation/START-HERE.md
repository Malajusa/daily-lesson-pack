# Daily Lesson Pack implementation handoff

**Prepared:** 8 September 2026, Australia/Perth.

This bundle turns the conversation into a creator-first delivery workflow. It is not a repository patch, live GitHub issue board, installed skill or classroom release.

| File | Purpose |
|---|---|
| `WORKFLOW.md` | Delivery sequence, milestones, gates, agent process and definition of done. |
| `DECISIONS.md` | Confirmed teacher requirements and all material superseded design variants. |

| `TRACEABILITY.md` | Searchable mapping from retained brainstorming ideas to work items. |

| `issues/` | 72 individual Markdown issue bodies suitable for creating work items. |

## How to use it

Open `WORKFLOW.md` first. Place the planning documents where your coding environment can read them, or commit reviewed copies under `docs/implementation/`. Do not overwrite a repository's existing `AGENTS.md` without reconciling its current instructions.

Give `CODING_AGENT_START.md` to the coding agent in the actual accepted checkout. Begin with the baseline/host audit, not the old patch. Work in dependency-ready, complete slices with independent review. Verify the installed package, not just a successful source merge.

## Scope boundaries

Your defaults are automatic; other teachers may personalise without changing them. Point-of-need teaching replaces year-based placement. Persistent preferences use real private storage with scoped overrides. All retained feature families are allocated; illustrative heuristic values are not automatically your permanent preferences.

The public repository was spot-checked, but its accepted commit, local state, live host and installed package must be verified during implementation. No repository tests or live agent runs were performed for this handoff. The earlier v2 patch is corrupt and must not be applied.

## Validation

The backlog has unique IDs, valid dependencies and no dependency cycles. Every item has scope, an owner, acceptance tests and traceability labels. These checks validate the planning bundle only; they do not establish implementation quality.
