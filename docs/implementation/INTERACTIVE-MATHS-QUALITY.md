# Interactive mathematics quality correction — 9 October 2026

Mr Slay review exposed a gap between broad teaching principles and enforceable
lesson requirements: topic labels substituted for goals, worked answers appeared
before questions, and text, notation and pictures did not consistently explain
the same step. The interactive adaptation now requires authored goals, observable
criteria, concept boundaries, purposeful representations and aligned exit tasks.
Each teaching state has one point, an unsolved starting question where relevant,
and corresponding explanation, mathematical notation and a visual model.

Counting tasks need suitable quantity/count notation, not an arbitrary equation.
Independent tasks may deliberately remove a scaffold. Fractional quantities and
bars remain valid where they support the actual concept; conversion must explain
the invariant quantity and its different units. The four review domains remain
separate. Structural coverage never certifies teaching quality.

The new checker binds inventories and declared scene/state reviews to a source
digest. Negative tests cover missing goals/planning fields, scene identities,
roles, null content, state inventories, incomplete entry/reveal review coverage,
stale source and blank/null/numeric lesson identities. Complete synthetic reviews
still leave teaching quality unverified.

Validation: 251 repository tests ran successfully, one skipped. Four changed
skill entry points passed the skill validator. Complete archive and eight
standalone component archives passed digest/manifest verification and dependency
closure in clean extraction directories. A separate reviewer ran seven blind
teaching cases, preserved valid alternatives, found structural bypasses and
verified their repairs. The final identifier probes included complete synthetic
reviews, so missing coverage could not mask the rejection. Both extracted maths
and QA components run all ten focused checker tests.

Source reconciliation: live main f86c6e4 was the base. Installed rc.3 instruction
changes were preserved from plugin 0.1.2, whose provenance names 1ebd4c4; the
object was unavailable in the source clone, so this is byte-preserving integration
of the installed instructions, not a claim that the missing source commit was

This remains an unreleased workflow candidate, 3.10.0-rc.4. No main merge, stable
tag, classroom pilot, general host acceptance or production activation occurred.
The browser adaptation keeps application verification in the application repo;
it does not manufacture pack release evidence. Rollback is the feature commit
revert or restoration of the previously verified private plugin release.
